# さくらプラザ・ホール 指定席予約（試作版）

戸塚区民文化センター さくらプラザ・ホール（全451席＋車椅子席2＋親子室6）の公演向けに、
「来た人順の自由席」を「映画館のような指定席」に変えるための試作Webアプリです。
お客様はスマホで座席表から席を選んで予約し、代金は当日受付で現金で支払います。

公演は1回のみを前提としており、公演情報は単一の設定として保持します。

## 使い方（お客様）

1. ページを開くと、そのまま座席表が表示されます（公演名・日時・料金は画面上部に表示）。
2. 1階席／2階席タブを切り替え、空席をタップして最大8席まで選べます（座席表は初期表示でホール全体が収まる「全体」表示。プリセットボタン（100%〜150%）のほか、座席表をピンチ（2本指で広げる・つまむ）しても全体の倍率から200%まで自由に変えられ、大きな倍率では左右スクロール）。
3. 申込画面で席ごとに券種（大人・子供など）を選び、名前・電話番号・備考を入力 → 内容確認 → 予約完了。完了画面に予約番号（SK-0001形式）と、その番号のQRコードが出ます。予約内容は LINE・Gmail・カレンダーにも送れます。
4. 当日は受付でお名前と予約番号（またはQRコード）をお見せのうえ、現金でお支払いください。予約確認ページ（予約番号＋電話番号）でもQRコードを再表示できます。

料金は券種ごとに設定します（種別：大人 2,000円／子供 1,000円）。予約には席ごとに券種名と料金が
そのまま記録されるため、後から公演設定の料金を変更・削除しても、記録済みの予約金額は変わりません。

## 使い方（スタッフ）

画面右上の「スタッフ用」から入室します（スタッフ共有のパスコード方式）。
パスコードには初期値がありますが、ここには記載しません。**運用開始時に
必ず公演設定から変更してください**（初期値のままだと、スタッフ画面に
警告が表示されます）。

- **受付**: 予約一覧を名前・予約番号・電話番号で検索。各予約に「来場チェックイン」「支払い済み」トグル、予約キャンセル（席を解放）。
  - **QRで受付**: 「QRで受付」ボタンでカメラが開き、お客様のQRコードを読み取ると該当予約がそのまま表示されます（読み取りは端末の BarcodeDetector、無い環境では同梱の jsQR を使用）。カメラが使えない場合は予約番号の手入力でも表示できます。新しいサーバ処理は追加しておらず、入室時に読み込んだ予約データから検索します。
  - 支払いのタイミングは予約ごとに柔軟に運用できます。たとえば事前に知人・団員経由で現金を受け取った（手売り前売り）場合は、その時点で「支払い済み」を押しておけば、当日は来場チェックインだけで済みます。
- **当日販売**: 空席をタップして即販売（支払済として記録。購入者名は任意、空欄なら「当日」）。席ごとに券種を選ぶと金額は自動計算されます（金額の手入力はありません）。集計は記録された金額で行うため、後から公演料金を変更しても過去の売上は変わりません。
- **販売設定**: 「販売しない」席をタップで切替。列ごとの一括ON/OFFも可能。デフォルトは全席販売。
- **集計**: 予約数／支払済数／売上（支払済合計）／未払い合計／残席に加え、券種別の内訳（予約席数・支払済席数・売上）を表示。
- **公演設定**: 公演名・日付・開演時刻・券種と料金・料金注記（「子供料金は小学生以下が対象です」等、お客様画面に表示）・メモを編集。券種は追加・改名・料金変更・削除が可能で、削除しても記録済み予約には影響しません。試作データの初期化もここから。

## 座席データについて

- 公式座席表PDF（hall_zaseki2021.pdf）を1席ずつ転記しました（転記仕様はリポジトリ外の調査メモに基づく）。
- 2階席92席と見切れ席10席は公式図面と一致しています。
- 1階席は公式固定席数が359席ですが、図面に描かれた席を数えると369席あり、10席の差があります（理由は図面からは特定できず）。アプリでは描かれた全席をデータ化し、実在しない／使わない席は「販売設定」で公演ごとにOFFにして吸収する設計です。**本番運用前にホール側・スタッフでの確認が必要です。**

## クラウド同期（Phase 2）

環境変数 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` がビルド時に設定されていると
クラウドモードになり、予約・座席状態・販売設定が Supabase 経由で全端末に同期されます
（設定が無ければ従来どおりこの端末の localStorage のみに保存するローカルモード）。

- お客様の予約はサーバ側 RPC で料金を再計算し、二重予約を防ぎます。
- 座席の空き状況は Realtime で他の端末にも反映されます。
- スタッフ操作はパスコード（公演設定から変更可。初期値のままでは警告が表示されるため、運用開始時に変更すること）を RPC で照合します。
- お客様はトップページの「予約確認」から、予約番号＋電話番号で自分の予約を確認できます。

**セットアップ（必須・1回だけ）**: Supabase ダッシュボードの SQL Editor で
`supabase/migration_sakura.sql` を実行してください。
このマイグレーションを適用するまで、クラウドモードの画面は接続エラーになります。

その他の Phase 2 機能: 予約一覧 CSV ダウンロード（受付・集計）、集計画面からの印刷、
予約完了画面の「Gmailで自分に送る」「カレンダーに追加」、おすすめ席表示（1階中央5〜10列）、
階ごとの残席・残りわずか表示、受付の「未払いのみ」フィルタ、予約締切設定。
追加機能: 予約ページと予約控えの LINE 共有ボタン、完了画面・予約確認への予約番号QR表示、
受付のQRチェックイン。

## 制限（正直なところ）

- 席の「仮押さえロック」（選択中の席を他者が取れないようにする仕組み）は未実装です。
  ただし申込確定はサーバ側で原子的に検証するため、二重予約そのものは起きません
  （先に確定した予約が優先され、後から申し込んだ方には選び直しの案内が出ます）。
- スタッフ認証は共有パスコード方式です（個人アカウント化は今後の課題）。
  クラウドモードでは照合はサーバ側（sha256）で行われますが、**ローカル（試作）モードでは
  パスコードが端末の localStorage に平文で保存されます**。試作用途の割り切りであり、
  実運用はクラウドモードで行ってください。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm run test     # vitest（座席データ整合性・予約ロジック）
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果の確認
```

## 本番化の次ステップ

1. **席の仮押さえロック**: 選択〜申込完了の間、席を数分間ロックして競合を減らす。
2. **QR受付**: 予約完了画面にQRコードを出し、受付ではスタッフが読み取ってチェックインできるようにする。
3. スタッフ認証（パスコード→個人アカウント化）と監査ログ。
