# さくらプラザ・ホール 指定席予約（試作版）

戸塚区民文化センター さくらプラザ・ホール（全451席＋車椅子席2＋親子室6）の公演向けに、
「来た人順の自由席」を「映画館のような指定席」に変えるための試作Webアプリです。
お客様はスマホで座席表から席を選んで予約し、代金は当日受付で現金で支払います。

公演は1回のみを前提としており、公演情報は単一の設定として保持します。

## 使い方（お客様）

1. ページを開くと、そのまま座席表が表示されます（公演名・日時・料金は画面上部に表示）。
2. 1階席／2階席タブを切り替え、空席をタップして最大8席まで選べます（座席表は左右スクロール・拡大縮小ボタンあり）。
3. 名前・電話番号・備考を入力 → 内容確認 → 予約完了。完了画面に予約番号（SK-0001形式）が出ます。
4. 当日は受付でお名前と予約番号をお伝えのうえ、現金でお支払いください。

## 使い方（スタッフ）

画面右上の「スタッフ用」から入室します。**試作版パスコード: `1234`**

- **受付**: 予約一覧を名前・予約番号・電話番号で検索。各予約に「来場チェックイン」「支払い済み」トグル、予約キャンセル（席を解放）。
  - 支払いのタイミングは予約ごとに柔軟に運用できます。たとえば事前に知人・団員経由で現金を受け取った（手売り前売り）場合は、その時点で「支払い済み」を押しておけば、当日は来場チェックインだけで済みます。
- **当日販売**: 空席をタップして即販売（支払済として記録。購入者名は任意、空欄なら「当日」）。金額は単価×席数で自動計算されます（前売り・当日とも同一料金）。集計は記録された金額で行うため、後から公演料金を変更しても過去の売上は変わりません。
- **販売設定**: 「販売しない」席をタップで切替。列ごとの一括ON/OFFも可能。デフォルトは全席販売。
- **集計**: 予約数／支払済数／売上（支払済合計）／未払い合計／残席を表示。
- **公演設定**: 公演名・日付・開演時刻・料金（1席単価）・メモを編集。試作データの初期化もここから。

## 座席データについて

- 公式座席表PDF（hall_zaseki2021.pdf）を1席ずつ転記しました（転記仕様はリポジトリ外の調査メモに基づく）。
- 2階席92席と見切れ席10席は公式図面と一致しています。
- 1階席は公式固定席数が359席ですが、図面に描かれた席を数えると369席あり、10席の差があります（理由は図面からは特定できず）。アプリでは描かれた全席をデータ化し、実在しない／使わない席は「販売設定」で公演ごとにOFFにして吸収する設計です。**本番運用前にホール側・スタッフでの確認が必要です。**

## 試作版の制限（正直なところ）

- **データはこの端末の localStorage のみに保存されます。** お客様のスマホで入れた予約は、スタッフのスマホには届きません。複数端末での同期は本番フェーズで実装します。
- パスコード（1234）は試作用の簡易なものです。本番ではスタッフ認証を付けます。
- 席の「仮押さえロック」（選択中の席を他者が取れないようにする仕組み）は未実装です（同期とセットで本番フェーズ）。

## 開発

```bash
npm install
npm run dev      # 開発サーバ
npm run test     # vitest（座席データ整合性・予約ロジック）
npm run build    # 型チェック + 本番ビルド
npm run preview  # ビルド結果の確認
```

## 本番化の次ステップ

1. **Supabase同期**: 予約・座席状態・販売設定をクラウド化し、お客様の予約がスタッフ全員のスマホにリアルタイムで届くようにする（ロジック層 `src/lib/logic.ts` は純粋関数で分離済みのため、保存先の差し替えがしやすい構成）。
2. **席の仮押さえロック**: 選択〜申込完了の間、席を数分間ロックして二重予約を防ぐ。
3. **QR受付**: 予約完了画面にQRコードを出し、受付ではスタッフが読み取ってチェックインできるようにする。
4. スタッフ認証（パスコード→個人アカウント化）と監査ログ。
